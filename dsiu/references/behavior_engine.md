# DSIU Behavior Engine

The strongest cross-domain part of DSIU: it puts humans, software, teams, AI agents,
and organizations under one model. Behavior is not random. **Behavior is output.**

## The producer stack

> Behavior = input + environment + rules + pressure + incentives + memory + available paths + feedback

1. **Input** — what the system receives (data, events, what a person sees/hears/reads).
2. **Environment** — the surrounding field (quiet vs chaos; a hot/throttled vs clean machine; high vs low demand).
3. **Rules** — internal laws (beliefs, habits, identity for humans; code, permissions, policy for software).
4. **Pressure** — forces movement (deadlines, pain, competition, money, threat, opportunity, urgency). Pressure creates *movement*, not necessarily *good* movement.
5. **Incentives** — systems move toward reward and away from cost. Often the most powerful lever.
6. **Memory** — past experience creates bias, skill, confidence, instinct, automatic responses.
7. **Available paths** — systems do what is *easiest*, not what is *best*: friction, defaults, shortcuts, layout, timing, distance.
8. **Feedback** — the primary teacher: action → result → correction → next action.

## The core rule

> Do not fight behavior directly. Find what is producing the behavior. Change the
> producer. Behavior follows.

A person repeats a habit because the condition-stack keeps producing it. A business
keeps hitting the same bottleneck because the process-chain keeps outputting it. An AI
keeps generating weak results because its intake, instruction hierarchy, memory,
constraints, or feedback loop is producing that behavior. A computer runs badly because
startup, services, drivers, background tasks, thermals, storage, and permissions are
shaping the output. **Same pattern, different system.**

## Control points (where you change the path)

Input point · Environment point · Rule point · Pressure point · Reward point ·
Memory point · Path point · Feedback point.

Instead of *"try harder,"* ask: What input is shaping this? What environment is causing
it? What rule is controlling it? What incentive is pulling it? What feedback is teaching
it? What path is easiest right now? What bottleneck keeps repeating?

## Worked example — "I can't focus"

| Producer | Diagnosis | Upgrade |
|---|---|---|
| Input | too many notifications | remove notifications |
| Environment | noisy room | clear the desk / change room |
| Rules | no clear start condition | set one starting rule |
| Pressure | task feels too big | shrink to first 5 minutes |
| Incentives | no immediate reward | add a reward |
| Available paths | distraction is easier than work | make distraction harder |
| Feedback | no visible progress | track visible progress |

Behavior changes because the *system* changed, not because effort increased.

## The highest version

> Behavior is the visible output of hidden system conditions.
> To change behavior, alter the conditions.
> To upgrade behavior, redesign the process.
> To break a limit, find the control point the limit depends on.

Note on "breaking boundaries": this never means violating consent or forcing entry.
The legitimate version is — break the boundary of your *current capability* by finding
the hidden control point and redesigning the process.
